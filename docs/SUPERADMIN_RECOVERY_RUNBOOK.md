# Super Admin Emergency Access, TOTP Setup & Credential Rotation Runbook

**Document Status:** Production Operational Runbook  
**Applicable Scope:** CloseDesk Platform Super Admin Infrastructure  
**Author:** Principal Backend Security Engineer  
**Last Verified:** November 2026  

---

## 1. Authentication Architecture Overview

Super Administrator authentication on the CloseDesk platform employs a hardened two-tier gate:

1. **Tier 1 — Primary Password Verification:**
   - Evaluated via `POST /api/superadmin/login`.
   - Verified using salted scrypt cryptographic hashing (`scrypt:<salt>:<hash>`) with timing-safe comparison.
   - Successful authentication returns an initial session token and HttpOnly cookie with claim `stepUpVerified: false`.
   - **Pre-step-up sessions cannot execute platform mutations** (any attempt to create tenants, reconfigure email protocols, or rotate credentials returns `403 Forbidden`).

2. **Tier 2 — Secondary Factor Step-Up:**
   - Evaluated via `POST /api/superadmin/verify-pin`.
   - Accepts one of three independent verification inputs:
     1. **RFC 6238 TOTP (Recommended Production):** 6-digit dynamic code generated by any standard authenticator app (Google Authenticator, Microsoft Authenticator, 1Password, YubiKey Authenticator).
     2. **Emergency Recovery Code:** 8-character single-use break-glass code (e.g. `A1B2-C3D4`) verified against hashed records.
     3. **Secondary PIN Verification (Local Dev / Fallback):** 4-digit static PIN stored with salted scrypt hashing.
   - Upon successful verification, the session is elevated to `stepUpVerified: true`, unlocking platform administration capabilities for 24 hours.

## 2. Environment Variables & Secret Configuration

The following environment variables govern platform security and must be configured in Netlify / server hosting environments:

| Environment Variable | Description | Example / Format | Required In Production |
| :--- | :--- | :--- | :---: |
| `CD_SESSION_SECRET` | 256-bit random secret used for HMAC-SHA256 session token signing and verification. | High-entropy string (64+ hex characters). | **YES** |
| `SUPERADMIN_TOTP_SECRET` | Base32-encoded 160-bit secret key used for RFC 6238 TOTP token generation and verification. | `JBSWY3DPEHPK3PXP...` (Base32 format). | **YES** |
| `SUPERADMIN_RECOVERY_CODES` | Comma-separated list of SHA-256 hashed single-use emergency recovery codes. | `8c6976e5...a4f,5e8848...9c1` | **YES** |

> [!IMPORTANT]
> Never commit raw passwords, TOTP secrets, or session signing keys to version control. Set these in Netlify Environment Variables (`Site settings > Build & deploy > Environment`).

## 3. Operational Procedures

### 3.1 Initial Setup of RFC 6238 TOTP on an Authenticator Device

To configure a new authenticator device for the Super Admin:

1. **Generate a Random Base32 Secret Key:**
   Run the following Node command locally:
   ```bash
   node -e "const { generateRandomSecret, generateOtpAuthUri } = require('./src/lib/totp'); const secret = generateRandomSecret(); console.log('SECRET:', secret); console.log('URI:', generateOtpAuthUri('admin', 'CloseDesk', secret));"
   ```
2. **Add Secret to Environment Variables:**
   Set `SUPERADMIN_TOTP_SECRET=<generated_secret>` in your production environment variables.
3. **Scan into Authenticator App:**
   - Import the `otpauth://totp/...` URI into your authenticator app, or generate a QR code using a local offline tool:
     ```bash
     npx qrcode-terminal "otpauth://totp/CloseDesk:admin?secret=<SECRET>&issuer=CloseDesk"
     ```
   - Scan the QR code using Google Authenticator, Microsoft Authenticator, or 1Password.
4. **Verify Live Code:**
   Test by submitting the 6-digit code on the `/api/superadmin/verify-pin` verification modal in the Super Admin Console.

### 3.2 Emergency Break-Glass: Lost Authenticator Device

If the primary authenticator device is lost, destroyed, or unavailable:

#### Step 1: Use a Pre-Generated Emergency Recovery Code
1. Log in to `/superadminlogin` using your primary Super Admin username and password.
2. In the **Secondary PIN Verification** prompt, enter one of your unused 8-character emergency recovery codes (e.g. `A1B2-C3D4` or `a1b2c3d4`).
3. The server compares the SHA-256 hash of your input against `SUPERADMIN_RECOVERY_CODES`.
4. Upon match, the server issues an elevated session (`stepUpVerified: true`) and allows console access.

#### Step 2: Immediately Rotate the TOTP Secret
1. Follow Section 3.1 to generate a new Base32 TOTP secret.
2. Update `SUPERADMIN_TOTP_SECRET` in Netlify / hosting dashboard.
3. Trigger a redeploy or environment variable reload.
4. Scan the new secret into your replacement authenticator app.
5. Generate fresh recovery codes (see Section 3.4).

---

### 3.3 Catastrophic Disaster Recovery: Both Password and Second Factor Lost

If both the Super Admin password and secondary factor credentials are lost, access must be restored via the break-glass database administrative console:

#### Step 1: Generate a Salted Scrypt Hash for a New Password
Run the following command locally using Node:
```bash
node -e "const { hashPassword } = require('./src/lib/authCrypto'); console.log('NEW_HASH:', hashPassword('TemporaryEmergencyPassword#2026!'));"
```

#### Step 2: Direct Database Update via Firebase CLI or Firebase Console
1. Open the [Firebase Console](https://console.firebase.google.com/) for your project.
2. Navigate to **Realtime Database > Data**.
3. Expand the `superAdmin` node.
4. Locate the Super Admin record (e.g. `superAdmin/0`).
5. Update the `password` field with the new scrypt hash generated in Step 1:
   ```json
   "password": "scrypt:<salt>:<hash>"
   ```
6. If needed, update the `pin` field with a temporary 4-digit PIN:
   ```json
   "pin": "1234"
   ```

#### Step 3: Invalidate All Existing Sessions
In the Firebase Realtime Database:
1. Navigate to `system_security/sessions/admin`.
2. Set:
   ```json
   {
     "minSessionVersion": 999,
     "revokedBefore": 1999999999,
     "revokedAt": 1999999999
   }
   ```
3. This invalidates all tokens currently issued to any user across all browsers immediately.

#### Step 4: Log In and Re-Establish Security
1. Log in with the temporary credentials.
2. Immediately change password via the console.
3. Configure your replacement TOTP authenticator device.

### 3.4 Generating Emergency Recovery Codes

Emergency recovery codes should be generated and stored securely in a company password manager or physical vault:

1. **Generate 5 Random Recovery Codes:**
   ```bash
   node -e "const crypto = require('crypto'); const { hashRecoveryCode } = require('./src/lib/totp'); const codes = Array.from({length: 5}, () => crypto.randomBytes(4).toString('hex').toUpperCase().match(/.{4}/g).join('-')); console.log('PLAINTEXT CODES (Store in vault!):', codes); console.log('HASHED ENV VALUE:', codes.map(hashRecoveryCode).join(','));"
   ```
2. **Store Plaintext Codes:** Store the plaintext codes in an encrypted password manager or offline safe.
3. **Configure Environment Variable:** Set the comma-separated hashed output to `SUPERADMIN_RECOVERY_CODES`.

---

### 3.5 Routine Credential Rotation Procedure

1. **Super Admin Password Rotation:**
   - Navigate to **Super Admin Console > Settings > Change Password**.
   - Input current password, new password, and confirmation.
   - Submitting executes `POST /api/user/password`, which:
     - Verifies current password.
     - Hashes new password with `crypto.scryptSync`.
     - Increments `sessionVersion` in `system_security/sessions/{sub}`.
     - Automatically terminates all other active sessions across all devices.
2. **Secondary PIN / TOTP Rotation:**
   - Update `SUPERADMIN_TOTP_SECRET` in environment variables.
   - Or update `pin` under `superAdmin/0` using `hashPassword('newPin')`.

## 4. Verification Checklist

Before signing off on any credential rotation or recovery incident, verify:
- [ ] Primary password login accepts only the new password.
- [ ] Older passwords fail and produce audit logs.
- [ ] Pre-step-up session (`stepUpVerified: false`) is blocked from mutating tenants.
- [ ] TOTP 6-digit code validates correctly within the current 30-second window.
- [ ] Emergency recovery code validates correctly and grants elevated session.
- [ ] All previous sessions receive `401 Unauthorized` due to `sessionVersion` increment.
- [ ] Deterministic test suite passes: `npm run test:cd02`.
- [ ] Baseline audit passes: `npm run audit:cd01`.
